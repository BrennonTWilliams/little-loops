# BUG-2837: Unknown writer mutates tracked agents/*.md mid-session

## Summary

> **RESOLVED — not a defect.** See § Resolution. The writer was an ad-hoc
> LLM-driven ENH-2714 prefix-pruning measurement session, not automation. The
> original characterization below (a "strip") was also wrong: the example blocks
> were *moved*, not deleted. Retained verbatim for the investigation record.

During an ordinary editing session, all nine `agents/*.md` files were rewritten
in place — `<example>` blocks stripped from their YAML frontmatter
`description:` fields — with no such edit requested or made. Three untracked
`.loops/ab-arm-{a,b,c}.yaml` files appeared in the same session. **The test
suite has been experimentally ruled out as the cause.** The actual writer is
unidentified.

The user-visible harm: tracked source files silently acquire uncommitted
changes, which then ride along in anyone's next `git commit -a` or get
accidentally staged by a broad `git add`.

## Current Behavior

Observed 2026-07-26 on `main`, in a session whose only intentional edits were
to `scripts/little_loops/cli/**` and `scripts/tests/**`:

```
 M agents/codebase-analyzer.md
 M agents/codebase-locator.md
 M agents/codebase-pattern-finder.md
 M agents/consistency-checker.md
 M agents/loop-specialist.md
 M agents/plugin-config-auditor.md
 M agents/prompt-optimizer.md
 M agents/web-search-researcher.md
 M agents/workflow-pattern-analyzer.md
?? .loops/ab-arm-a.yaml
?? .loops/ab-arm-b.yaml
?? .loops/ab-arm-c.yaml
```

The diff shape, for every file, is removal of the `<example>` / `<commentary>`
blocks from the frontmatter `description:` block scalar:

```diff
   Essentially a "super Grep/Glob tool" that combines multiple searches ...
 
-  <example>
-  User: "Where are all the API routes defined?"
-  → Spawn codebase-locator to find route definitions across the codebase
-  <commentary>Returns file paths grouped by purpose, not implementation details.</commentary>
-  </example>
```

All nine files shared an identical mtime (`18:56:42`); the three `ab-arm` YAML
files shared an earlier one (`18:46`), so there are plausibly **two distinct
writers**, not one.

The `ab-arm-*.yaml` files self-describe as `ENH-2714 prefix-pruning A/B, arm a.
... Temporary measurement loop.` — i.e. FSM measurement loops that were never
cleaned up, not test fixtures.

## Expected Behavior

Nothing outside an explicit user request or an explicitly-invoked generator
(`ll-adapt --apply`, `ll-generate-skill-descriptions`) should modify tracked
files. Temporary measurement loops should be written under a run-scoped
directory (`${context.run_dir}/`, per the MR-3 loop-authoring rule) or cleaned
up on exit, not left as untracked repo litter.

## Root Cause

**Unknown — this issue is scoped as an investigation, not a fix.**

Ruled out by controlled experiment:

- **The pytest suite.** Initially suspected via mtime correlation (both
  timestamps fell inside full-suite runs). Disproved directly: `git checkout --
  agents/`, `rm -f .loops/ab-arm-*.yaml`, then a full
  `python -m pytest scripts/tests/` run (16,434 passed, 42 skipped) left
  `git status --short` **completely clean**. The correlation was coincidental.
- **A writer inside `little_loops/`.** `grep` for `<example>` across the package
  source returns nothing, and no module writes to a repo-root `agents/` path —
  every test that touches an `agents` directory uses `tmp_path`.

Remaining candidates, in rough order of likelihood:

1. **A lifecycle hook** in `hooks/hooks.json` (SessionStart / PreCompact /
   SessionEnd / Stop) or one of its adapter scripts.
2. **A background or scheduled FSM loop** — this is the strongest lead for the
   `ab-arm-*.yaml` files, which are self-identified ENH-2714 measurement arms
   and would have to be generated by something that runs loops.
3. **A host-side agent-definition sync** that normalizes frontmatter
   descriptions to fit a token budget (cf. `ll-verify-skill-budget`,
   `ll-generate-skill-descriptions`) firing without an explicit invocation.

## Implementation Steps

1. Reproduce with an audit trail: snapshot `agents/` hashes, then run a normal
   session and diff. `fs_usage`/`opensnoop` on the repo path, or a filesystem
   watch, will name the writing process directly — this is the fastest path to
   attribution and avoids further guessing.
2. Inspect `hooks/hooks.json` for any entry that writes rather than reads, and
   check the `hooks/adapters/claude-code/` scripts.
3. Grep for whatever generates `ab-arm-*.yaml` (`ENH-2714` A/B harness) and
   determine what triggers it and why it targets `.loops/` rather than a
   run-scoped dir.
4. Once identified: make the writer explicit-invocation-only, or redirect its
   output to a run-scoped/gitignored path.
5. Add a regression test asserting a representative workflow leaves
   `git status --porcelain` clean for `agents/`.

## Impact

- **Users**: uncommitted edits to tracked agent definitions appear without
  provenance; `git commit -a` or `git add -A` silently ships them. Agent
  `description:` fields drive model-invocation routing, so a stripped
  description could measurably degrade agent selection if committed.
- **Risk**: Medium. Silent mutation of tracked files is a correctness and trust
  problem even though each individual diff is small and reversible.
- **Effort**: Small once attributed; attribution is the bulk of the work.

## Steps to Reproduce

**Not yet reliably reproducible on demand.** Observed once, across two distinct
timestamps within a single session. What is known:

1. Work a normal editing session on `main` (the observed one edited only
   `scripts/little_loops/cli/**` and `scripts/tests/**`, ran the full pytest
   suite three times, and ran `ll-loop show`, `ll-check-links`,
   `ll-verify-package-data`, `ll-verify-docs`).
2. Run `git status --short` and observe the nine modified `agents/*.md` files
   and the three untracked `.loops/ab-arm-*.yaml` files.

Negative result worth preserving — this is what exonerates the test suite:

```bash
git checkout -- agents/ && rm -f .loops/ab-arm-*.yaml
python -m pytest scripts/tests/    # 16,434 passed, 42 skipped
git status --short                 # clean — nothing reappears
```

Because the trigger is unknown, attribution should come from a filesystem
audit (step 1 of Implementation Steps) rather than from further attempts to
reproduce by guesswork.

## Investigation Findings (2026-07-26, session 2)

### The diff is a MOVE, not a strip — prior characterization was wrong

Earlier notes described the change as `<example>`/`<commentary>` blocks being
*stripped* from the frontmatter `description:`. They are not deleted. They are
**relocated verbatim** into a newly-appended `## When to use` body section at the
end of each file (`git diff agents/prompt-optimizer.md`: `-201/+174`, with the
example text appearing on both sides). This is a **description-token-budget
optimization**: shrink the frontmatter payload (which is loaded into every
session's static prefix) while preserving the content in the body (which is not).

That reframes the search. The writer is not a linter deleting noise; it is
something trying to reduce static-prefix cost.

### Every deterministic in-repo candidate is ruled out

| Candidate | Verdict | Evidence |
|---|---|---|
| pytest suite | Ruled out | Full run leaves `git status` clean (prior session) |
| `little_loops` package source | Ruled out | No `write_text` to any repo-root `agents/` path; no module contains `<example>` or `When to use` emitting logic |
| `ll-generate-skill-descriptions` | Ruled out | Module has zero `agents` references |
| `ll-adapt-agents-for-codex` / `adapt.py` | Ruled out | Read-only over `agents/`; writes only `.codex/agents/*.toml` |
| `test_adapt_agents_for_codex.py::TestRealAgentsIntegrationGuard` | Ruled out | Touches the real `agents/` dir but is assert-only |
| `ab_writer.py` | Ruled out | Writes only `ab.json` under `run_dir` |
| Installed plugin cache (`~/.claude/plugins/cache/little-loops/ll/1.151.1/agents/`) | Ruled out | Still carries the **original** un-moved form, so the transform is not a packaging step |
| Project `hooks/hooks.json` | Ruled out | No entry writes to `agents/` |

A repo-wide grep for `## When to use` across `scripts/`, `hooks/`, `skills/`,
and `commands/` returns **zero** hits. No code in this project emits that
heading. The transform is therefore **LLM authorship**, not a deterministic tool.

### Timeline correlation: the ENH-2714 prefix-pruning A/B run

`.loops/.history/` shows two loop runs immediately preceding the pollution:

| Run | Window |
|---|---|
| `ab-arm-a` | 18:47:24 → 18:49:38 |
| `ab-arm-b` | 18:55:08 → **18:56:28** |
| `agents/*.md` batch write | **18:56:42** (14s after arm b exited) |

Both arms are the ENH-2714 **prefix-pruning** A/B measurement (cf. the untracked
ENH-2839, "measure ENH-2714 realized prefix savings"). Arm b's `events.jsonl`
shows it ran `/ll:confidence-check FEAT-2414` — read-mostly, and it does not
itself touch `agents/`. But the *theme* matches the diff exactly: an agent
working the prefix-savings problem shrinking frontmatter descriptions across
`agents/` is the only hypothesis consistent with both the semantic nature of the
edit and the 14-second gap.

**Conclusion: cluster 1 (`agents/*.md`) and cluster 2 (`.loops/ab-arm-*.yaml`)
share a cause — an ad-hoc LLM-driven prefix-pruning measurement session.** The
`ab-arm-*.yaml` files were hand-authored by that session (they self-describe as
"Temporary measurement loop"), not generated by `ab_writer.py`, which explains
both their bare-`.loops/` placement (an MR-3 violation no code path would make)
and their absence from every grep of the source tree.

This downgrades the bug: there is **no rogue automated writer**. The residue is
un-cleaned-up manual experiment scaffolding.

### Passive trap armed

`agents/` restored clean at 19:28:05; baseline hashes at
`md5 agents/*.md`. If the pollution does **not** recur during normal sessions,
close this as `cancelled` with the negative result recorded, and instead file the
real defect: prefix-pruning experiments must write scaffolding under
`${context.run_dir}/` and must not edit tracked `agents/*.md` in place.


## Resolution

**Closed `cancelled` — no code defect exists.** There is no rogue automated
writer. Both artifact clusters are un-cleaned-up scaffolding from a manual,
LLM-driven ENH-2714 prefix-pruning measurement session:

- `agents/*.md` — an agent shrinking frontmatter `description:` payloads to
  reduce static-prefix cost, moving the example blocks into a `## When to use`
  body section. Semantic authorship; no tool in this repo emits that heading.
- `.loops/ab-arm-*.yaml` — hand-authored by the same session (they self-describe
  as "Temporary measurement loop"), which is why they match no grep of the source
  tree and why they sit in bare `.loops/` in violation of MR-3.

Full attribution evidence — the ruled-out candidate table and the 14-second
timeline correlation against the `ab-arm-b` run — is in § Investigation Findings.

`agents/` was restored clean at 2026-07-26 19:28:05 and `.loops/ab-arm-*.yaml`
are already gone. Nothing to fix, nothing to regression-test: a test asserting
`git status --porcelain` stays clean for `agents/` would guard against a writer
that does not exist.

**Follow-up not filed.** The one durable lesson — prefix-pruning experiments
should write scaffolding under `${context.run_dir}/` and must not edit tracked
`agents/*.md` in place — is a working convention for whoever runs the next
ENH-2714 measurement, and is recorded here rather than as a separate issue.


## Impact if not fixed

The `agents/` directory accumulates unexplained diffs that contributors either
commit by accident or repeatedly revert without knowing why.
