# BUG-3163: ll-adapt --host qwen mirrors omit skill companion files

## Summary

Observed in a live Qwen Code session: `/ll:audit-issue-conflicts` failed to load its companion prompt — `ReadFile .qwen/skills/audit-issue-conflicts/conflict-detection-prompt.md` → File not found — and had to glob-recover the file from the source tree (`skills/audit-issue-conflicts/`).

**Root cause**: `QwenEmitter.emit_skill` (`scripts/little_loops/adapters/qwen.py`) writes only `.qwen/skills/<name>/SKILL.md` and never copies the sibling companion files that the ENH-494 500-line convention depends on. Its idempotency check returns `skipped` early when SKILL.md matches, so companion drift is never repaired even by a re-run. FEAT-3159, the FEAT-3155 spike, and EPIC-3154 never mention companion files — an oversight, not a scoped-out decision.

**Blast radius**: 10 of the 18 mirrored qwen skills reference 22 companion files that are absent from `.qwen/skills/`:
- wire-issue (6): behavior-parity, graph-discovery-layer, learning-targets, output-report, prose-dependency-gate, static-coupling-layer
- audit-issue-conflicts (4): conflict-detection-prompt, interactive-prompts, verbatim-output, examples
- create-loop (3): loop-types, reference, templates
- confidence-check (2): reference, rubric; configure (2): areas, show-output
- capture-issue, decide-issue, format-issue, manage-issue, spike (1 each: templates / reference / plan-template)

In this repo the model can glob-recover from `skills/` (degraded but functional). In an end-user project that only ran `ll-adapt --host qwen --apply` there is no source tree to fall back to — affected skills hard-fail. The packaged-extension path (`qwen-extension.json` → `"skills": "skills"`) is unaffected: it points at the full source tree.

**Expected behavior**: `ll-adapt --host qwen --apply` mirrors each skill directory completely (SKILL.md + companions, excluding the codex-only `agents/` subtree); re-runs repair companion drift; a wiring test guards parity.

**Related (out of scope)**: `KimiEmitter` and `GeminiEmitter` have the identical single-file gap in `.kimi-code/skills/` and `.gemini/skills/` — track as a follow-up.


## Current Behavior

`ll-adapt --host qwen --apply` writes only `.qwen/skills/<name>/SKILL.md` for each eligible skill. Companion files living beside the source SKILL.md (e.g. `skills/wire-issue/behavior-parity.md`) are never copied into `.qwen/skills/<name>/`. Adapted SKILL.md bodies reference those companions with relative links/paths, so Qwen Code resolves them against the mirror directory and gets File not found. The emitter's skip check (`qwen.py:69-72`) compares SKILL.md content only and returns early, so re-runs never repair companion drift either.

## Expected Behavior

`ll-adapt --host qwen --apply` mirrors the full skill directory: SKILL.md plus every companion file (excluding the codex-only `agents/` subtree). Re-runs detect and repair companion drift (changed files re-copied, stale mirror files pruned). A wiring test fails when a `.qwen/skills` mirror lacks a companion its source has.

## Motivation

Adapted-host skills are silently broken: 10 of 18 mirrored qwen skills reference 22 companion files that are absent. In this repo the model can glob-recover from `skills/`, but in end-user projects that only have the adapted mirror, those skills hard-fail at the first companion read. Undermines the ENH-494 500-line companion convention and the FEAT-3155 "near-passthrough" trust story for the qwen surface.

## Proposed Solution

Add a shared companion-sync helper to `scripts/little_loops/adapters/core.py` (e.g. `_sync_skill_companions(source_dir, out_dir, apply, quiet) -> bool`) that copies every regular file under the source skill dir except `SKILL.md` and the codex-only `agents/` subtree, prunes mirror companions no longer present in source, and returns whether anything changed. `QwenEmitter.emit_skill` calls it and folds the result into its adapted/skipped status so companion drift defeats `skipped`. Then regenerate `.qwen/skills` mirrors and extend tests. Kimi/Gemini emitters gain the same call in a follow-up.

## Implementation Steps

1. Add `_sync_skill_companions(source_dir, out_dir, apply, quiet)` to `core.py`: walk the source skill dir (skip `SKILL.md` and `agents/`), copy changed files, prune stale mirror files, return a changed flag; dry-run prints intended copies without writing.
2. Wire into `QwenEmitter.emit_skill`: run the sync even when SKILL.md is unchanged; return `"skipped"` only when SKILL.md and companions are all in sync.
3. Regenerate mirrors (`ll-adapt --host qwen --apply`) and confirm all 22 companions land in `.qwen/skills/` byte-identical to source.
4. Add the unit + wiring tests, then run `test_qwen_adapter.py` and `test_wiring_skills_and_commands.py` plus the broader adapter suite.
