# ENH-3745: Usage derive freshness after retention: processed-boundary floor, per-source held status and safe checkpoint reads

## Summary

Preserve validated scan progress after retention, diagnose malformed metadata safely, and publish source freshness from source-local successful derivation. Keep ingestion and derived boundaries separate so skipped work cannot overwrite historical proof. Own the shared source pending/completion and minimal generation/dependency storage consumed by readers and ENH-3770. Land after ENH-3744's pure candidate proof and prune veto; ENH-3770 then implements reconciliation, held-source additive derivation, below-checkpoint retries and parser-refresh preservation. Each issue lands and passes the local suite independently.

## Current Behavior

On inspected `main`, `scripts/little_loops/session_store/lifecycle.py::_set_usage_derive_checkpoint` stamps surviving `MAX(raw_events.id)` even after prune/rebuild. `_derive_usage_incremental_conn` converts metadata before checking its version and treats max-below-checkpoint as a destructive replay trigger. The same branch initializes a new store; simply replacing every missing checkpoint with skip would break first-enable derivation (see `scripts/tests/test_session_store_incremental_usage.py`). Both cursor writers publish a complete ingestion boundary even when holds skipped usage; `_refresh_codex_usage_source`'s unchanged-size/mtime fast path bypasses derive-version checks. Ordinary incremental Codex catch-up also deletes/replays unheld source observations; new completion/dependency facts need invalidation at that existing mutation seam.

`lifecycle.py::refresh_usage_source` advances past malformed/non-object complete lines; `scripts/little_loops/session_store/sessions.py::parse_codex_rollout` silently skips malformed JSON/non-objects and uses strict UTF-8, so stream decoding can raise before the JSON handler runs. `scripts/little_loops/session_store/usage_refresh.py::refresh_raw_events` parses before its source transaction and may return `unchanged` despite rejected physical input. A sanitizer refusal rolls back the entire refresh/backfill transaction, leaving no durable diagnostic. `lifecycle.py::usage_source_freshness` returns `source_untracked` immediately when no cursor exists and performs unguarded numeric conversions outside its database-read handler. `scripts/little_loops/session_store/backend.py::connect_readonly` enables query-only access without beginning a pinned read transaction.

The 64-byte tail witness does not prove an unchanged historical prefix. `rebuild` deletes/replays observations before its stamping call; checkpoint changes alone cannot preserve their row identity/cost. `refresh_raw_events` deletes linked usage/cursors and global progress before committing a separate `needs_rebuild` phase. Those reconciliation/preservation changes belong to ENH-3770, not this issue's implementation gate.

## Expected Behavior

- Retention cannot lower a validated same-version scan floor or trigger destructive replay solely because surviving raw max fell. Allocation sequence, surviving max and retained usage are never positive processing proof.
- A pristine/live-only store can establish initial progress without deleting anything. Missing, malformed, contradictory or version-changed proof in an established store produces bounded incomplete diagnostics and preserves usage, holds and prior metadata until protected recovery is available.
- New semantic completion requires both complete acquisition of the certified native range and ENH-3744's correspondence proof against actual post-write proof observations on the publishing connection (defined below). Represented candidates and recognized benign/terminal omissions can complete; skipped/unrepresented work cannot.
- Fully acquired, represented sources can publish positive completion in this issue. New usage on a held source that today's writer skips stays pending until ENH-3770; this issue does not claim safe additive held-source derivation. An unrelated completed source can remain fresh.
- Ingestion may advance while derivation is incomplete. Keep ingestion offset/line/stat/tail separately from the last successful derived boundary/version/publication time. Preserve that older internal boundary; an absent/unproved boundary remains unknown as-of.
- Durable scoped pending/failure state survives restart and retention. A sanitizer refusal preserves ingestion rollback while recording a content-free diagnostic through a separately guarded failure-only transaction, including when no cursor exists.
- Caller-owned committed reads can obtain admission, figures and source proof in one revision. External source comparisons cannot manufacture a fresh zero or a newer boundary for older figures.

## Impact

- **Priority**: P2 — processing/freshness proof diverges after retention.
- **Effort**: Medium-large — checkpoint guards, source storage, acquisition accounting and reader seam.
- **Risk**: Medium-high — a false boundary can label incomplete figures fresh; validate both cursor writers and every local ingestion seam.
- **Breaking Change**: No public payload/return-type break; optional reader keyword and append-only internal storage. Incomplete refresh status must be truthful rather than an unconditional `complete`.

## Proposed Solution

Consume ENH-3744's pure proof, validate checkpoint state before derive decisions/publication, preserve a justified floor, and persist source-local pending/completion separately from ingestion. Factor pure retained-state completion reads for quality and allow freshness to reuse a caller's pinned read connection. Supply ENH-3770 with shared pending state and minimal observation dependency witnesses; it owns reconciliation and mutation.

## Program Design

### Types

Factor `_valid_usage_checkpoint` into one current-version/non-negative-integer rule over committed metadata. Check version before conversion; handle malformed values and SQLite numeric/type edge cases with bounded reasons. Missing is distinct from proved zero. Validate `sqlite_sequence.seq` for `raw_events`: checkpoint above a valid sequence is contradictory; a positive checkpoint with absent/malformed sequence is unprovable. A missing sequence row is compatible with an independently proved zero checkpoint in a genuinely empty raw store, not evidence that a missing checkpoint equals zero. Sequence values may reject a checkpoint but never raise it or prove processing. Validate source offsets, line/raw bounds, version, status and scope too.

Frozen `SourceDeriveCompletion` records source host/session/generation/version scope, source revision, status (`complete`, `pending`, `unprovable`), bounded reason, nullable successful boundary and outstanding-work disposition. Its semantic reader uses basis `semantic` only for proved complete state, otherwise `none`; `legacy` belongs exclusively to the public compatibility comparison. Missing semantic state is `unprovable` with a bounded unavailable reason. Internal positions, native identifiers and witness bytes never become shareable reason strings.

Represent ingestion and successful derived witnesses separately. Keep `usage_source_cursors` as ingestion state; its `derived_raw_event_id` and legacy `status` cannot become the new semantic certificate. The concrete storage contract below supplies the missing facts through the next available append-only migration; do not pin an issue-era version (inspected `main` is v61 on 2026-10-07).

The shared refresh-pending disposition has explicit `raw_cache` and `usage` outstanding-work components. Raw parser replacement records both. Usage-only catch-up can resolve only its usage component; it cannot acknowledge sessions/messages/tools or other raw-derived caches. An unbounded full rebuild acknowledges only the components/range it actually consumed, and unresolved usage remains pending. `needs_rebuild` reflects either outstanding refresh component. ENH-3770 owns the acknowledgement decisions and authoritative API/CLI reread after rebuild; this issue supplies storage/helpers, without a second refresh journal. The same scoped seam can retain explicit successful original-source refresh acquisition evidence for ENH-3770's narrowly permitted qualification recovery; it is not ordinary replay authority or a legacy certificate.

Include a source-scoped pending/retry lower bound sufficient for ENH-3770 to revisit unresolved raw below/equal to the scan high-water. It schedules work; it is not native order or processing proof. A rejected source line with no raw row instead records its first unresolved native line/offset and bounded reason. Do not fabricate a raw-ID bound or store malformed bytes. Invalid scope/bounds stay unprovable. Resolved-neighbor pruning and other-source replay preserve these records.

ENH-3770 also consumes unresolved native-conflict disposition scoped to the affected observation/source generation and version. Prefer sufficient retained conflicting raw/audit evidence; where retention could otherwise erase that obligation, use this shared bounded pending storage rather than a separate conflict ledger. Ordinary replay or unrelated closure cannot silently clear conflict qualification invalidation. ENH-3770 owns detecting the conflict and deciding mutations/recovery; this issue supplies the durable scope/helper seam.

**Mandatory handoff, not deferred storage:** provide the minimal current applied-value supplier and consumed qualification-dependency frontier wherever existing observation columns cannot express them, with source/generation/native-position scope and explicit unavailable legacy values. Define writer/update/read helpers for ENH-3770 so values and their actual supplier, or qualification and its actual dependencies, can change atomically. No automatic first-seen-position substitution or legacy certification. This issue defines/persists the interface and tests storage/transaction behavior; ENH-3770 owns mutation decisions. Full aggregate beyond-prefix as-of integration is deferred separately.

Migration starts conservatively: do not seed successful derived boundaries or semantic completion from legacy `complete` ingestion cursors/global checkpoints. Establish new positive state only from actual acquisition and committed candidate proof. ENH-3744 and ENH-3770 add no competing migration or candidate ledger.

SQLite `INTEGER` positions/revisions require exact integer storage, non-negative bounds and signed-64-bit range; native line numbers start at one. Add `CHECK` constraints for enums and simple bounds and validate compound scope/range invariants in shared helpers. JSON is not an arbitrary payload container: only the fixed, content-free witness fields described below are permitted.

`acquisition_witness_json` contains only device, inode, size, mtime_ns and tail_sha256 from the guarded acquisition (nullable when unavailable); those cheap fields support change detection/CAS, never full-prefix continuity. Define `_USAGE_ACQUISITION_VERSION = "enh3745-v1"` for physical-line accounting/canonical acquisition evidence, independently of `_USAGE_DERIVE_VERSION` and the rebuild fingerprint. A mismatch leaves acquisition evidence unprovable, without certifying or mutating it. `original_acquisition_json` contains only verified source scope, acquired byte/line range, acquisition version, derive version and source revision from an explicitly successful canonical original-source comparison. Absent/failed acquisition leaves it NULL. ENH-3770 compares both versions before scoped recovery; this evidence is never ordinary replay authority. Positions remain internal.

`generation_id` and obligation/dependency IDs are opaque durable tokens, with no native-order or trust meaning. Allocate a generation on initial tracking or incompatible acquisition; changing it cannot clear older obligations or certify continuity. Source paths retain existing lookup spellings. Verified host/session may become known only from actual acquisition, never filename/inode guesses. Preserve an older success's own host/session/generation/version tuple when the current scope changes.

Source revisions start at one and increase on every committed ingestion, completion, pending/failure or invalidation change, including raw-only and unchanged-output acquisition accounting. Retain the source head as a tombstone across cursor deletion/recreation; never reset its revision. A first failure captures an absent-head sentinel; its failure-only insert succeeds only if the head is still absent. Subsequent failure/ack helpers compare the exact prior head revision and attempt scope. A pending row's `revision` separately identifies its last merge; acknowledgement compares both captured revisions from the same snapshot.

Merge pending with minimum known first bounds, maximum known last/end bounds and component union, retaining the obligation ID. Raw/line bounds are inclusive; byte ranges are `[first_offset, end_offset)`. Never infer native order from raw bounds. `whole_source` dominates a bounded range and explicitly represents unavailable upper/lower bounds without fabricated positions. A bounded obligation needs at least one proved complete bound pair; an unbounded axis cannot supply partial-clear permission. Recovery must prove every affected candidate across the captured scope/range, not just reach the lower bound. For merged gaps at lines 5 and 20, recovery through 10 clears nothing. Partial coverage returns false and retains the entire obligation; finer splitting is ENH-3770's future decision, not this helper's implicit behavior. Delete a row only when both components are clear. Resolving older-generation work cannot acknowledge the current generation; generation changes, later appends and retention alone never resolve it.

No new table has a cascading foreign key to `raw_events`, cursors or `usage_events`. Native scope/position witnesses survive prune/replacement; nullable raw IDs are references, not proof. Observation deletion/recreation invalidates affected facts before mutation; never transfer old witnesses solely by native key or reused row ID. `usage_events.id` is already AUTOINCREMENT; retain that property and explicitly remove deleted observations' current witness/frontier rows in the same transaction after enumerating affected completion dependencies. Clear only the bounded dependency set for a successfully re-proved completion. Enumerate reverse dependencies before mutation, including sources whose dedup supplier is elsewhere, and leave unprovable/over-limit dependent scopes pending. Use ENH-3744's existing limits for proof/dependency collection rather than a second budget or host-wide scan. Proof-limit results retain durable unresolved disposition with bounded `usage_proof_limit`; a retry is not promised to resolve it.

Before production prune deletes raw needed by an unresolved acquisition/conflict/refresh obligation, `_plan_raw_prune` conservatively vetoes the affected source with bounded `source_recovery_pending`, including an outstanding `raw_cache` component after usage has completed. Existing semantic/checkpoint/age gates remain necessary. Obligations without proved narrower bounds retain the whole source; unrelated and resolved neighbors remain independently eligible. Prune never acknowledges recovery or deletes pending records. This minimal storage-consumer veto prevents the new recovery seam from losing its own evidence; no new reconstruction algorithm belongs here.

Register all five tables in `_KINDLESS_TABLES`; keep them out of `_REBUILD_TABLES`, `_REBUILD_SEARCH_KINDS` and search events. Regenerate `schema_manifest.json` using `TestSchemaManifest`'s existing recipe. Migration creates empty state, pending and witness tables, with no seeded success/dependency evidence or legacy certification. Pre-migration query-only readers return unavailable for absent new tables without `ensure_db`, migration or fallback to another member.

### Signatures

- `backfill_usage_incremental(db: Path | str = DEFAULT_DB_PATH) -> int` — keep this contract and existing refresh/rebuild payload shapes. Carry a bounded internal derive disposition so zero inserted rows can be distinguished from skipped/unverified derivation; map it truthfully to refresh status.
- `usage_source_freshness(db: Path | str, source: Path, *, conn: sqlite3.Connection | None = None) -> dict[str, int | str | None]` — gain the optional caller-owned connection. With `conn`, require an already active pinned read transaction containing admission/figure reads and `PRAGMA query_only = 1`; inactive/autocommit or writable callers receive `unknown/read_snapshot_unavailable` without changing their connection. The caller supplies a committed read snapshot, not uncommitted writer state. Never open another history connection or begin/commit/roll back/close the caller's. Without `conn`, open strict read-only access and begin one owned read transaction before the first database read, then release only owned resources. Keep `status`, `reason`, `as_of` and `as_of_offset` keys/meanings.
- `read_source_derive_completion(conn: sqlite3.Connection, source_path: str, *, schema: str = "main") -> SourceDeriveCompletion` — committed-state reader. Validate generated attached aliases before SQL interpolation; preserve member/source scope. No source stat/parser/pricing/write normalization. ENH-3732 consumes this alongside candidate proof; historical quality qualification does not require a cursor or current source file.
- `read_observation_witness(conn: sqlite3.Connection, usage_event_id: int, *, schema: str = "main") -> ObservationWitness` — frozen supplier/dependency facts, with explicit unavailable legacy/missing-table state; no inferred witness.
- `record_source_acquisition(conn, scope: SourceScope, acquired: AcquisitionBoundary, witness: AcquisitionWitness, *, expected_head_revision: int | None) -> int` — update verified scope/acquired physical bounds and source revision after raw-only or unchanged-output acquisition without publishing completion. Rejected ranges are accounted separately and cannot become a success boundary. NULL expected revision means insert-if-absent, never reset an existing head.
- `record_source_pending(conn, pending: SourcePending, *, expected_head_revision: int | None) -> int`, `publish_source_completion(conn, completion: SourceDeriveCompletion, dependencies: tuple[CompletionDependency, ...], *, expected_head_revision: int) -> int`, `invalidate_usage_dependencies(conn, usage_event_ids: tuple[int, ...], source_scopes: tuple[SourceScope, ...], *, reason: str) -> None` and `write_observation_witness(conn, witness: ObservationWitness) -> None` — typed internal writer helpers; `conn` is `sqlite3.Connection`. Operate only in the caller-owned write transaction, never commit/roll back, and return the updated source revision where applicable. A revision mismatch performs no write and raises a bounded internal conflict, causing owner rollback/retry. `write_observation_witness` atomically writes the actual supplier and replaces its entire consumed qualification frontier.
- `acknowledge_source_pending(conn: sqlite3.Connection, obligation_id: str, consumed: ConsumedRange, *, expected_head_revision: int, expected_obligation_revision: int, components: frozenset[str]) -> bool` — storage seam for ENH-3770; only `usage`/`raw_cache`, only the covered obligation scope/range, false with no change on either revision mismatch or partial coverage. `ConsumedRange` includes verified scope, consumed first/last raw/line and first/end byte bounds plus explicit full-scope proof disposition. Whole-source obligations require proved full-scope consumption; a numeric upper bound alone cannot acknowledge a missing prefix. This issue tests the helper, not new recovery decisions.

`SourceScope`, `DerivedBoundary`, `AcquisitionBoundary`, `AcquisitionWitness`, `SourcePending`, `ConsumedRange`, `ObservationWitness`, `QualificationDependency` and `CompletionDependency` are frozen dataclasses mirroring the fixed scope/boundary/dependency fields; nullable positions explicitly mean unavailable. `ObservationWitness` includes `qualification_dependencies: tuple[QualificationDependency, ...]`, distinct from applied-value supplier position. Define finite reason/refusal-code enums and compound validation once for writers/readers. The post-rollback failure owner reuses `record_source_pending` under a new guarded transaction with its captured head revision/attempt witness; it does not invoke completion publication.

Consume the landed `usage_proof.py::inspect_usage_candidates` and `usage_proof_scope.py::collect_usage_proof_scope`/`inspect_retained_source`, including `UsageProofLimit`, for SQL read-back and decoding. Extend that shared collector with `schema: str = "main"` in this issue, qualifying every raw, observation, related-source and exact-link query with the same validated member alias. Two members never join by matching paths/native keys/raw IDs; absent new tables yield unavailable, not a read from `main`. Do not create a parallel proof collector.

Post-write proof runs on the publishing writer connection; pure completion/witness readers read stored facts and never invoke writes or a normalizer. Their multiple reads consume one active caller-owned query-only snapshot; an unavailable snapshot returns bounded unprovable facts without starting/changing a transaction. Attached alias validation requires a safe generated identifier and membership in `PRAGMA database_list` before interpolation; unknown, malicious or old-schema aliases return bounded unavailable. The optional freshness connection selects its `main` member; an attached completion/candidate read selects its explicit schema. The `db` argument is never reopened to compare another revision when `conn` is supplied.

### Call Path

`backfill_usage_incremental` → checkpoint validation/bootstrap decision → existing eligible derivation → ENH-3744 proof + acquisition disposition → atomic scan/pending/completion publication.

`refresh_usage_source` / `_refresh_codex_usage_source` → physical acquisition accounting + existing eligible derivation → distinct ingestion/derived publication → `usage_source_freshness`. Quality uses the pure retained-state read; ENH-3770 later consumes the pending/dependency handoff.

### Decision Rules

- **Checkpoint guard and bootstrap:** guard `_derive_usage_incremental_conn` before the existing delete/reset branch, both cursor publication sites, Codex's unchanged-file fast path and freshness numeric reads. Changes cannot be confined to `_valid_usage_checkpoint`/`_set_usage_derive_checkpoint`. Bootstrap requires both checkpoint keys absent, no prior replay-derived/non-live usage or replay holds, and no prior successful semantic derived boundary; live-only observations and initial ingestion-only tracking/pending/failure do not block it. That ingestion tracking is expected after pristine raw-only backfill, and an acquisition failure still prevents positive source completion. Derive eligible initial acquired work without deleting/repricing any observation, then establish progress from successful work and source proof. Legacy-unlinked observations, a partially missing checkpoint pair and old-version/invalid existing metadata never take this exception. Established missing/version-changed/contradictory proof skips and reports incomplete; protected recovery is ENH-3770.
- Preserve the previously validated same-version floor across retention: after justified scanning use `max(previous same-version floor, scanned retained raw bound)` (the existing `MAX(raw_events.id)` only when that retained range was actually scanned/accounted for). A smaller surviving raw max alone is not a reset. Never restamp invalid progress as current or use allocation high-water to manufacture a floor. Existing rebuild stamping consumes the same safety rule; row/cost-preserving rebuild reconciliation remains ENH-3770.
- Checkpoint publication consumes an explicitly validated prior floor and the actually scanned/accounted bound plus derive disposition; a stamping helper cannot infer success by querying the surviving maximum again. Missing/invalid/version-changed established proof remains untouched even at the existing rebuild stamping site, and skipped/unverified work cannot publish positive completion. This changes checkpoint publication here; ENH-3770 still owns replacement of rebuild's earlier observation mutation.
- Every global scan advance past unresolved work commits its generation/version-scoped pending disposition in the same write transaction. Without durable pending state, do not make skipped candidates unreachable. Publish completion from ENH-3744's outcomes against actual post-write proof observations read back by SQL on the publishing connection, not prospective inserts/writer return values, cursor status, conservation-hold absence or global progress. ENH-3770 owns iteration of old pending candidates; this issue supplies durable bounds and leaves them pending meanwhile.
- **Completion is a conjunction:** account for every complete physical source line in the claimed prefix before parser skips/normalizer omissions. Persist coverage beginning at offset zero (or establish it by full verified re-acquisition of the entire claimed prefix), then extend only under compatible continuation. Acquisition disposition plus candidate correspondence must cover the same source/version/range. A retained-only candidate pass, first-seen later offset or legacy cursor cannot prove the earlier physical inventory. Distinguish blank/recognized benign records and proved producer terminal omissions from decode/non-object failures. An unterminated tail stays pending. Publish only a successful prefix; do not jump over a missing candidate. Held history without outstanding work is not itself incomplete, but a held append skipped by today's writer is pending until ENH-3770.
- Account for stream decoding before ordinary parser iteration as well as JSON/non-object rejection, including Codex strict UTF-8 failures. Add internal acquisition accounting while keeping ordinary yielded event types/API contracts compatible. Rejected bytes never enter history storage, logs or exception text. Ordinary local `_backfill_raw_events`/`backfill_raw_events` records source-local pending/failure alongside its successful inserts; both refresh paths consult those dispositions.
- Acquisition accounting starts at path-to-handle/header recognition, not only at `iter_events`. `backfill_raw_events(jsonl_files=..., host="codex")` currently calls `handles_from_paths` before opening its guarded connection; `_codex_header_session_id` can decode bytes beyond line one and fail before a handle exists. Preserve bounded source-only failure evidence with explicitly unknown session/native scope; do not guess a verified identity. Cover public raw-only and full `backfill(...)` owners and refresh header acquisition. A caller owning a larger backfill transaction must roll back all its writes before any separately guarded refusal diagnostic is persisted; `_backfill_raw_events` never commits/rolls back that caller's work.
- **Sanitizer refusal:** preserve ENH-3751's whole-call rollback for Claude/Codex refresh and raw-only backfill; valid rows before/after the refused line remain un-ingested and cursor, derived boundary and checkpoint remain unchanged. Carry only a bounded reason (`sanitization_refused`, allowed refusal code and first refused line/offset), never input bytes. After the ingestion transaction fully rolls back, a diagnostic-only transaction may persist that failure. Compare-and-swap against the failed attempt's source scope/version, prior committed cursor/completion revision and acquisition witness; a concurrent/newer successful refresh invalidates the comparison, so the delayed refusal cannot taint it. This transaction writes only failure evidence and does not publish processing proof. `_backfill_raw_events` never commits its caller's transaction. Keep public refusal/per-source `skipped` behavior, including `refresh_raw_events` keeping earlier sources' commits. If diagnostic persistence fails, preserve rollback and report a bounded incomplete reason; never substitute success.
- Read pending/failure evidence before returning `source_untracked`; a source with no cursor can still report its durable refusal/decode reason with null as-of. Missing boundaries never borrow ingestion or row timestamps. Unknown/unreadable/changed sources cannot fabricate fresh zero.
