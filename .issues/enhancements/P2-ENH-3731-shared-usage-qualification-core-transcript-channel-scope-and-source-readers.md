# ENH-3731: Shared usage qualification core, transcript channel scope, and source readers

## Summary

Add the shared qualification contract for canonical stored-usage figures and route the source readers through it. This child owns `qualify_usage`/`UsageQualification` with fixed row admission, the logical `channel=` acquisition scope on both coverage selectors, and the source-side consumers (`aggregate_usage`, `cost_attribution`, `waste_attribution`, `ll-ctx-stats` all-history/per-model and the stored cache-rate path). Sibling children ENH-3732 (quality) and ENH-3733 (snapshot/dashboard) consume this contract and are blocked by this issue.

## Parent Issue

Decomposed from ENH-3723: Canonical usage qualification across source and snapshot consumers. The parent's recorded **Decision (2026-10-04, `/ll:decide-issue`, commit `01747bb96`)** is authoritative and is not reopened here:

1. Legacy NULL provenance is conservative: audit-only, exactly like explicit `unknown`; no provenance-presence column or compatibility label.
2. Complete `estimated` rows are admitted in general consumption reports with an explicit `estimated`/`mixed` label; cache rate stays measured-only; quality trends require all-measured composition.
3. Decision 4 (Option A, refined): `channel=` scope on `select_usage_coverage`/`select_usage_observations`; the store-wide ambiguity gate and ENH-3543's contract are unchanged (narrowing it belongs to ENH-3730).

## Current Behavior

`ObservationGroup.total` gates on coverage and component presence; `aggregate_usage` can return numeric components with unknown provenance. `ctx_stats._aggregate_usage_events` publishes `ObservationGroup.subtotal` as canonical `usage_by_model.totals` with cost availability `available`. `waste_attribution` has its own coverage-only numeric gate. A partial row (input 10, output 2, cache-read 4, cache-creation NULL) with unknown **or measured** provenance and stored cost $1 publishes canonical input/output/cache-read/cost from source readers. `_compute_cache_rate_from_usage` separately requires measured usage and a complete denominator.

## Expected Behavior

- **Terms (used consistently below).** *Admitted* = all four `TOKEN_COLUMNS` are valid non-bool integers ≥ 0; NULL is missing and any other value is invalid. *Eligible* = admitted **and** row provenance is `measured` or `estimated` (NULL, explicit `unknown` and unrecognized strings all read as `unknown` through `row_provenance`, so they are never eligible). Missing `cost_usd` alone is a pricing gap, not a partial-token row and does not affect admission. A canonical cost additionally requires a finite, non-bool numeric value ≥ 0 from every contributor; reject invalid costs without affecting otherwise qualified tokens.
- Row admission precedes figure completeness: an observation that is not admitted is audit-only for every canonical figure, regardless of provenance. An admitted row with `unknown` provenance is also audit-only.
- Qualification evaluates **all in-filter annotated audit contributors** in the requested aggregate, including coverage-unresolved rows. `selected_rows` certifies coverage only; using that subset as the qualification population can hide unresolved contributors. Coverage reconciliation precedes output/report filters; admission/provenance/pricing checks apply to the returned population, so an out-of-window unknown-provenance row alone does not invalidate an otherwise qualified window. If any in-population contributor fails the figure's contract, the canonical figure is unavailable with a bounded reason. Audit subtotals are sums of valid components and are distinctly labeled; derived totals never turn missing components into zero. A stored numeric `cost_usd` alone cannot qualify an audit-only row.
- Figure prerequisites (after coverage reconciliation and row admission):

  | Figure | Prerequisites |
  | --- | --- |
  | Token component / four-component consumption | Every in-population row eligible (admitted ⇒ every component valid). |
  | Cost / cost per issue | Every contributor eligible with a finite stored non-bool `int`/`float` cost ≥ 0 and a finite aggregate; no read-time repricing; no priced-subset sums. Dollars are API list-price estimates. |
  | Waste tokens / percentage | **One qualification per loop over the full joined population** (reading B: row admission **plus** the provenance gate) governs both `tokens_total` and `tokens_wasted`; keep the existing **input + output** definition, wasted-run subset sum and nonzero-denominator rule. Admission still requires all four token columns, so a row with NULL cache columns now blanks that loop's waste figures (behavior change vs. today's input/output-only check). |
  | Session cache hit rate | Every contributor eligible **and measured** (`estimated` excluded); input, cache-read and cache-creation form the complete denominator; zero denominator is unavailable. Cache operand fields (`cache_read_tokens`, `cache_write_tokens`, `uncached_tokens`) stay measured-only too. |

- **Availability metadata follows the value; audit counts describe the evidence.** Every published canonical stored-usage `token_provenance` entry (`ObservationGroup.entry`, `_waste_provenance`, `_cache_rate_provenance`) is `available` iff its value is present, otherwise `unavailable`; canonical pointers never emit `partial`. Preserve real known/missing counts even when qualification fails. Add `invalid_count` and `rejected_contributors` separately; never reset a valid-component count to zero to force availability. For each component, valid known + NULL missing + present invalid = contributors. A row rejected for several prerequisites counts once in `rejected_contributors`; coverage failure and zero denominator are group/figure failures, not missing or invalid rows. Every stored-cache pointer carries the actual selection coverage, equal to `cache_rate_coverage`; unavailable coverage must not inherit `counted_entry`'s `non_overlapping` default. The JSON invariant checks value, availability, coverage and the figure's bounded `qualification_reason` together.
- **Separate reasons for independent figures.** `aggregate_usage` and `cost_attribution` rows gain token `qualification_reason` and `cost_qualification_reason`, matching ENH-3733. Qualify tokens and cost separately; a missing/invalid cost cannot appear in the token reason or blank qualified tokens. All four token columns qualify together, including all-or-none emission of `gen_ai.usage.*` attributes. Waste rows gain base token `qualification_reason` plus `waste_pct_qualification_reason`. Stored cache results retain public `qualification_reason` for the rate; each operand's provenance entry carries its own figure reason. A figure's value is `None` iff its figure reason is non-NULL. Qualified zero operands remain numeric while a zero-denominator ratio is unavailable with `zero_denominator`. Existing keys remain.
- `select_usage_coverage(..., channel: str | None = None)` and `select_usage_observations` with the same argument: accepted non-NULL arguments are exactly `live`, `transcript`, `rollout`. Resolve logical channels with `row_channel` (including legacy NULL/absent channel with a session ID) before grouping and before computing `ambiguous_cross_channel`. Validate arguments before schema/query early returns; an unsupported argument always raises `ValueError`, including on an empty/legacy store (when iterating the observation generator). Default `channel=None` preserves the current store-wide gate and does not silently drop unrecognized stored channel values. `since`/run filters still apply after coverage reconciliation; BUG-3735 moves host/session output narrowing after that reconciliation as well. **Rows outside the requested channel are excluded from `audit_rows`/`selected_rows`/group subtotals entirely.** Selectors stay coverage-only and keep numerically/provenance-audit-only rows in coverage-selected `selected_usage_events`.
- **Freshness contract**: qualification of a stored observation and completeness of the current source are separate. Preserve qualified historical/as-of Claude/Codex figures with existing freshness, lag reason and as-of metadata, subject to the corrected BUG-3735 overlap verdict; stale/unknown cannot read as current. A cache rate over only the complete subset of selected observations is not permitted. Characterize text and JSON behavior before extending to other hosts.
- `ll-ctx-stats` all-history/per-model JSON keys keep their existing public numeric keys, show canonical values only when qualified, expose labeled audit subtotals distinctly, and never mark metadata `available` for an unavailable canonical field. Qualified tokens with missing model pricing stay canonical while cost is unavailable.
- Qualification is read-time policy: no history migration, derive-version bump, automatic rebuild or refresh is required. Incremental replay, full rebuild and unchanged tail refresh cannot infer producer qualification from legacy payload shape or stored numeric cost. Explicit re-ingestion from a verified original source can acquire new producer evidence through the existing `refresh_raw_events` workflow; that is distinct from replay and remains outside this implementation's mutations.

## Proposed Solution

Factor a small immutable `UsageQualification` (eligibility, provenance label `measured`/`estimated`/`mixed`/`unknown`, bounded reason code, audit known/missing/invalid and rejected-contributor counts) from the `ObservationGroup`/coverage chokepoint in `token_provenance.py`:

- `qualify_usage(group: ObservationGroup, *, require_cost: bool = False, measured_only: bool = False) -> UsageQualification` — a pure function of group state; always enforces fixed row admission and the provenance gate first. After admission the only figure-specific variation is whether `cost_usd` is also required (`require_cost`) and whether `estimated` is excluded (`measured_only`, cache rate); both flags can only tighten the result, never relax the four-column or provenance gate. No caller-supplied admission policy. `mixed` is an aggregate label only; never store it. The coverage check is delegated to `group.coverage()`; the label matches today's `aggregate_provenance` masking semantics (computed over all in-filter annotated audit contributors, admitted or not).
- `ObservationGroup.add` gains per-row counters sufficient for each combination of `require_cost`/`measured_only`, with invalid-value accounting before arithmetic. `qualify_usage` needs no second pass and counts a multiply rejected row once. Its immutable result snapshots counts; later `group.add()` cannot mutate an earlier result. Define the public fields in Program Design; internal accumulator names remain an implementation choice.
- Treat `ObservationGroup.subtotal` as an explicitly labeled audit operation (recommended: rename to `audit_subtotal` and gate inside `total()`), including when used to sort reports.
- **No new audit surface for dollars.** Per-provenance token and cost subtotals already live in `token_provenance[ptr].composition`; never add `cost_usd` to `ObservationGroup.channel_subtotals()` — preserve that existing public shape. Valid finite dollar audit subtotals remain labeled audit evidence when canonical cost fails (including an unpriced/invalid sibling); the no-priced-subset rule applies to canonical figures, not these audit subtotals. ENH-3733's snapshot uses its own totals today; its new qualification columns are a separate, explicitly versioned export change. State in the docs that dollars have no separate audit-subtotal surface.
- **Reason-code precedence** (first applicable group-wide failure wins): populated unresolved coverage > `empty_selection` > `missing_token_component` > `invalid_token_component` > `unknown_provenance` > `not_measured` (when requested) > `invalid_cost` (cost figure) > `unpriced_contributor` (cost figure). Determine the failure across all contributors, independent of insertion order. Map `group.coverage() == "overlap_unresolved"` to `coverage_overlap_unresolved`, populated `"unknown"` to `coverage_unknown`, unexpected unresolved statuses to `unclassified`. Empty groups return `empty_selection` before the coverage-status mapping. Keep existing `coverage_reason` codes/prose untouched as separate diagnostics: never parse their semicolon-joined text or use `CoverageSelection.reason` to choose the shared code. `row_provenance` collapses unrecognized strings into `unknown`, so there is no `unrecognized_provenance` code. For stored-cache compatibility, both `unknown_provenance` and `not_measured` map to public `unverified_usage`; other codes pass through. Figure builders apply `zero_denominator` only after base qualification succeeds; `qualify_usage` does not return it.
- Add `channel` to both selectors in `history_reader/usage.py` and thread it through the coverage/ambiguity computation.
- Apply qualification in `aggregate_usage`, `cost_attribution`, `waste_attribution`, `ctx_stats._aggregate_usage_events` and `_compute_cache_rate_from_usage`.
- The stored cache reader computes one `qualify_usage(group, measured_only=True)` result over `selection.audit_rows` and reuses it for the rate, every operand and their metadata. Use that result and validated audit sums; default `ObservationGroup.total`/`entry` use general-consumption eligibility and must not recertify estimated cache operands. No new measured-only parameter on those methods is required. Replace coercing `_known_int` use and the complete-subset accumulator with strict validated arithmetic; keep `_known_int` and the separate direct-JSONL reader unchanged. Missing **output** disqualifies the stored rate even though output is not a denominator operand. After successful qualification, derive the rate from the full input/cache-read/cache-creation sums; zero denominator leaves those qualified operands at zero.
- Fix `_waste_provenance` and `_cache_rate_provenance` locally: build truthful count metadata with `counted_entry`, then set `availability` from the published value and attach the figure reason/invalid/rejected counts. Do not change `counted_entry`'s default behavior for unrelated callers.
- Keep snapshot (`queries.py`) and quality (`agent_quality.py`) untouched here; they are ENH-3733 and ENH-3732.

### Shared consumer handoff (2026-10-05)

- Empty groups report `empty_selection`; their synthetic `coverage() == "unknown"` is not a populated unresolved-coverage reason that masks emptiness. Populated unknown/unresolved groups retain coverage-first precedence. Test empty tokens and cost separately.
- Define proposed `USAGE_QUALIFICATION_POLICY_VERSION = 1` beside `qualify_usage` in `token_provenance.py`; `UsageQualification.policy_version` carries it. ENH-3733 exports that result's version, not a second literal. Intentional changes to admission/provenance/figure prerequisites/reason precedence update the version and the shared behavioral matrix together. Coverage policy and export allowlist versions remain separate.
- Export `USAGE_QUALIFICATION_REASONS` as a `frozenset[str]` containing the shared qualification codes, `coverage_overlap_unresolved`, `coverage_unknown`, `zero_denominator` and `unclassified`. It is the bounded handoff for ENH-3733, separate from unchanged coverage diagnostics and CLI absence/compatibility codes. Syntactic sanitization alone is insufficient: an arbitrary source-derived string can be ASCII snake_case and still disclose an ID. Unknown reasons become `unclassified`; no new enum or extensible registry is needed.
- Snapshot and other consumers qualify tokens with `require_cost=False` and cost separately with `require_cost=True`. Cost eligibility implies token eligibility; missing/invalid cost alone never blanks qualified tokens. The deterministic precedence above also applies when both `measured_only` and `require_cost` are true.
- Use the same validity checks in source and snapshot arithmetic. Invalid components stay in completeness/rejection accounting; they are neither coerced nor silently dropped and summed as a canonical complete subset. Add direct-mapping boolean tests and persisted negative/fractional/non-finite cases with one valid sibling.
- BUG-3735 owns scoped wildcard-overlap correctness. This issue's `channel=` acquisition scope runs before coverage analysis; it must compose with that repair in either landing order. It does not certify a host/session by removing possible cross-channel counterparts. Default `channel=None` preserves the coverage policy and acquisition population; byte-identical scoped results are not required where BUG-3735 corrects unsafe certification. Compare the channel-only commit with its immediate baseline, including that repair if already landed.
- Numeric validity applies before accumulation as well as qualification. Invalid values count as rejected contributors and remain intact in audit rows, but must not be added to numeric audit subtotals or provenance composition. Report valid-value audit sums with missing/invalid counts; never coerce strings/bools, let a string raise during addition, or emit NaN/Infinity in metadata. Test invalid direct mappings and SQLite-stored values through actual source consumers with a valid sibling; the canonical figure stays unavailable.
- Keep token sums as Python integers without float coercion, including sums above `2**53`. Cost accumulation must make both the finite total and overflow verdict independent of contributor order; naive repeated float addition is insufficient. Use a stable stdlib approach such as `math.fsum` for validated dollar totals and each provenance subtotal, handling `OverflowError` and non-finite results. Buffering/finalizing validated cost scalars is permitted; `qualify_usage` must not re-read raw rows, and totals/metadata must reuse the same finalized sums rather than rescan costs per pointer. Internal caching/accumulator design remains an implementation choice. Finite contributors whose aggregate overflows make cost unavailable with `invalid_cost`; preserve known counts and use `None` for the unrepresentable audit subtotal instead of Infinity. With no row-level failure, this aggregate failure has `rejected_contributors == 0` and every component `invalid_count == 0`. Tokens and any still-finite provenance audit subtotals remain available on their respective surfaces.

## Program Design

### Types

- `UsageComponentCounts` — new frozen dataclass in `scripts/little_loops/token_provenance.py`: `column: str`, `known_count: int`, `missing_count: int`, `invalid_count: int`. Counts describe valid numeric/NULL/present-invalid observations, respectively, independent of whole-row qualification.
- `UsageQualification` — new frozen dataclass in the same module: `eligible: bool`, `provenance: str` (`measured`/`estimated`/`mixed`/`unknown`), `reason: str | None`, `contributors: int`, `rejected_contributors: int`, `component_counts: tuple[UsageComponentCounts, ...]` in `AGGREGATE_COLUMNS` order, `policy_version: int`. `eligible` iff `reason is None`. Copy counts into immutable values; do not retain mutable component mappings. `rejected_contributors` counts each row failing any applicable admission/provenance/measurement/cost prerequisite once; group coverage failure can leave that count zero. Figure-level `zero_denominator` is outside this result.
- `ObservationGroup` (`token_provenance.py`, plain class) — today accumulates every row into every `AGGREGATE_COLUMNS` component with no row admission; a row missing one token column still feeds the other three.
- `CoverageGroup` / `CoverageSelection` (`history_reader/usage.py`, both `frozen=True`) — `channel=` scope changes which rows reach them, not their fields.
- Coverage values stay plain `str`: `non_overlapping`, `overlap_unresolved`, `unknown`. Provenance literals `"measured"`/`"estimated"`/`"unknown"` have no module constant (a separate `TokenProvenance` Literal lives in `subprocess_utils.py`).

### Decision Rules

- **Terms**: *admitted* = all four `TOKEN_COLUMNS` are valid non-bool integers ≥ 0; *eligible* = admitted and provenance `measured`/`estimated`. Use these two words only in this sense.
- **Row admission (fixed, first)**: all four `TOKEN_COLUMNS` (`input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`) must satisfy `type(value) is int and value >= 0`. NULL is missing; negative, float (including integral `3.0`), boolean and string mapping values are invalid. SQLite INTEGER affinity may persist booleans/integral floats/numeric strings as integers; validate the actual read value without inferring lost type history. Missing `cost_usd` alone does not reject a token row — it makes cost unavailable. A rejected row remains in `audit_rows`; only its valid components enter audit subtotals/composition.
- **Provenance**: `measured` and `estimated` are recognized; NULL, `unknown` and unrecognized strings all read as `unknown` through `row_provenance`. Aggregate label is `measured` if every contributor is measured, `estimated` if every contributor is estimated, `mixed` if both occur, `unknown` if any contributor is `unknown`. `mixed` is never stored.
- **Cache rate**: qualify all annotated audit contributors with `measured_only=True`, including the output-column admission prerequisite. Denominator is `input + cache_read + cache_creation`. Base failure blanks the rate and all operands; otherwise zero denominator blanks only the rate with `zero_denominator`. Operand reasons remain `None` with numeric zeros. Replace complete-subset/coercion logic only in the stored reader. Keep existing `counts` entries' `{"known", "missing"}` shape: rate known = contributors passing row prerequisites, rate missing = rejected-contributor count; operand known/missing = valid-component/NULL counts. Coverage/zero-denominator failure does not falsify counts. Expose operand invalid counts in an additive parallel `invalid_counts` mapping and full-population `rejected_contributors`, then use those to build pointer metadata.
- **Waste (resolved: reading B)**: keep `input_tokens + output_tokens`, the `_WASTED_RUN_PREDICATE` subset and `waste_pct` only when `tokens_total` is nonzero. One per-loop qualification over the full joined population (admission **and** provenance gate) governs both token figures. Preserve `tokens_total_missing` as joined rows missing input/output, and `tokens_wasted_missing` as wasted-run rows missing those operands; missing cache/provenance is a qualification rejection, not a fabricated input/output shortfall. Classify each operand pair once: either NULL operand makes it missing; otherwise either invalid operand makes it invalid; otherwise it is known. Add `tokens_total_invalid`/`tokens_wasted_invalid` and full-loop `rejected_contributors`. Non-wasted rows contribute known zero to the numerator by definition, even when their raw operand pair is missing/invalid. For each token figure, known = joined events minus that figure's missing and invalid pairs. Ratio known/missing/invalid counts equal the denominator-pair counts; they describe operand evidence, independently of the full-loop four-column qualification/rejection counts. Thus missing cache can blank the figures with zero missing input/output pairs, and zero denominator can blank the ratio with all pairs known. Ratio reason is the base failure if present, else `zero_denominator` when total is zero, else `None`; a qualified positive total with no wasted runs gives zero wasted tokens/ratio. Canonical-number fixtures explicitly set measured provenance; unknown fixtures remain unavailable.
- **Availability** is derived from the qualified value, independently of truthful audit counts (see Expected Behavior). Locally override `counted_entry`'s count-derived availability for stored cache/waste; retain unrelated callers' behavior. ### Codebase Research Findings

_Added by `/ll:refine-issue` — 2026-10-05 — based on codebase analysis:_

- **Waste admission — resolved reading (the wire pass left this open).** `waste_attribution` today never consults provenance or the cache/cost columns for admission: it requires only `input_tokens` and `output_tokens` non-NULL per row and gates `tokens_total`/`tokens_wasted` on `slot["group"].coverage() == "non_overlapping"`; provenance only feeds the reported `provenance` label. Two readings of "admit the full joined population" are possible: (A) row admission only (four `TOKEN_COLUMNS` non-NULL), or (B) row admission plus the fail-closed provenance gate. The recorded decision (parent Decision 1: NULL/unknown provenance is audit-only for canonical figures; Expected Behavior: "unrecognized stored provenance fails closed like explicit unknown") implies B for waste, and the figure table distinguishes cache rate only by adding *measured-only* (excluding `estimated`), not by being the sole provenance-gated figure. Under B the `_populate_waste_run` fixture (input 100, output 20, cache 0/0, NULL provenance, no session/host) flips `_WASTE_CORE_EXPECTED` `tokens_total`/`tokens_wasted`/`waste_pct` to `None`; under A it is unchanged. Under the settled reading B, the `tokens_total_missing`/`tokens_wasted_missing`/`waste_pct` keys and the `test_enh3543_usage_coverage.py` unresolved-overlap controls (all three figures `None`) must hold, and fixtures that need canonical waste numbers must set `provenance='measured'` explicitly rather than weakening the gate.
- **`unverified_usage` is a `ctx_stats` code, not a coverage reason.** Today's stored reader emits only `"unverified_usage"` (coverage `non_overlapping`, provenance not measured) or `None`; coverage codes and the four absence diagnostics have separate surfaces. This review makes the compatibility mapping explicit for shared `unknown_provenance`/`not_measured`, while adding an immutable shared qualification-reason allowlist rather than a registry. Existing coverage diagnostics remain untouched.
- **Current cache-rate gate vs the replaced behavior.** `reportable = coverage == "non_overlapping" and group.aggregate_provenance("input_tokens") == "measured"`; rows with all of input/cache-read/cache-creation present count as `eligible_events` and the rest as `excluded_events` (`counts["hit_rate_pct"] = {"known": eligible, "missing": excluded}`); `output_tokens` is never read. The `{"known": N, "missing": M}` count shape is asserted by `test_enh3656_stored_cache_rate.py` and must keep resolving, with `missing` now carrying the rejected-contributor count.
