# ENH-3770: Guarded usage reconciliation, held-source derivation and hold release (ENH-3744/3745 MP3)

## Summary

Replace destructive per-Codex-source catch-up, `rebuild` and parser-refresh replay with guarded, source-scoped reconciliation against committed usage observations; recover established unusable checkpoints without destructive reset; resume safe additive derivation on held sources; revisit outstanding candidates below the scan high-water; and release conservation holds only when proved safe. This is the reconciliation merge point MP3 of the shared Delivery Plan, split out of ENH-3744 on 2026-10-07. All three whole-issue prerequisites are `done` on inspected branch `main` as of 2026-10-08: ENH-3744's proof/prune-veto, ENH-3745's checkpoint/source-storage and ENH-3747's search survival. Read **ENH-3744 § Delivery Plan** for the fail-closed non-regression definition and the hazards that bind this issue.

## Current Behavior

On inspected branch `main`, ENH-3745 changed established missing/invalid/version-mismatched checkpoint handling to skip untouched, while pristine stores bootstrap without deletion. `_derive_usage_incremental_disposition` owns incremental mutation; `_derive_usage_incremental_conn` is now only a count wrapper. Per-Codex-source catch-up and `rebuild` still delete unheld observations before replay; `refresh_raw_events` still deletes linked observations and reallocates raw IDs before its separate derive phase. The delivered negative invalidation removes affected observation witnesses/frontiers, and parser invalidation gives every reverse-dependent source both usage and raw-cache obligations. Production writers do not yet populate observation witnesses. A temporary-store unchanged Claude rebuild replaced row IDs and changed deliberately stored historical costs.

`_backfill_usage_events` skips entire held sources, and the incremental `max_id <= checkpoint` early return misses outstanding work. `_write_host_usage_observation` prices before matching, updates Claude snapshots by raw-ID ingestion order, and falls through to INSERT for unkeyed audit rows. `normalize_host_usage` checks its state against the replay envelope but does not compare the payload's session identity with that envelope. Codex dedup sees only candidates within one replay invocation. Neither ingestion order nor a high-water checkpoint proves native source order or safe replacement. Codex qualification can legitimately change when a later `task_complete` supplies missing context. An unchanged parser-refresh retry still reports `needs_rebuild = False` even if a prior derive failed. The landed `pending_obligations` reader omits the persisted acquisition authority and obligation revision that guarded recovery/acknowledgement need. Parser refresh's `_record_replacement_acquisition` also skips previously untracked sources and does not update the acquired source boundary; a raw-only-backfilled source can refresh without durable pending, and appended recovery can leave the head behind its acquisition certificate. The private direct-file usage helper still mutates rawless candidates, and invocation-local Codex copy dedup ignores contradictory model context.

The landed handoffs also need focused extension. `usage_proof._fill_codex` captures context when the value record arrives, so a subsequent `task_complete` is absent from that request's dependency IDs. `collect_usage_proof_scope` discovers matching peer usage rows but omits their model/header/closure context and filters ordinary discovery by matching sessions. Both atomic source-refresh paths derive before `finalize_source_refresh` records acquisition; clean raw-only backfill creates no acquired head. Incremental pending capture covers held skips only. Finally, `write_observation_witness` currently rejects residual context dependencies when qualification is invalidated. Reusing these seams unchanged would omit required evidence, strand unheld work, or suppress first-time derivation.

## Expected Behavior

- Keep protected observations unchanged unless a safe mutation is proved. Semantically unchanged or older replay is an idempotent no-op, including row identity, stored cost, timestamps and provenance. A genuinely newer compatible native snapshot may update using its stored/native ordering proof; newly proved native context may permit a separate qualification mutation. Equal numeric values alone do not establish a semantic no-op; path aliases, larger raw IDs and equal values/timestamps alone prove neither generation nor order.
- Allow proved-distinct new requests on a source that still has conservation protection. Preserve old protected rows and the hold while unrelated new appends derive safely; hold removal is not a prerequisite for safe additive work. Unkeyed/wildcard legacy populations may prevent proving distinctness and stay conservative.
- Keep every unresolved scanned scope durably retryable, whether held or unheld. Record verified new acquisition before its reconciliation needs generation authority, and preserve supported stored-raw audit insertion without inventing qualification or historical lineage.

## Impact

- **Priority**: P2 — completes the retention-safe derive path after MP1/MP2.
- **Effort**: Large — guarded reconciliation across reset, catch-up, rebuild, parser refresh and hold release.
- **Risk**: High — a false mutation or hold-release proof can lose or double-count usage; destructive paths are replaced.
- **Breaking Change**: No

## Proposed Solution

Consume ENH-3744's pure `inspect_usage_candidates` proof and ENH-3745's source-local pending/completion storage to replace broad usage delete/reinsert with source-scoped reconciliation: compare with committed observations before any deletion, preserve unchanged rows (identity, stored cost, timestamps, provenance), replace values only on proved newer native evidence, apply only the explicitly proved qualification actions below, and release holds only on proved reconstructibility.

## Program Design

### Signatures

- `backfill_usage_incremental(db: Path | str = DEFAULT_DB_PATH) -> int` — keep the public contract; `rebuild(...)`, `refresh_usage_source(...)` and `usage_refresh.refresh_raw_events(...)` keep their return payload shapes. `RefreshResult.needs_rebuild` also reflects unresolved committed refresh-pending work, including an unchanged retry. Usage counts continue to count newly inserted observation rows only; replacement, qualification, no-op, search repair, completion publication and hold release contribute zero.
- `_derive_usage_incremental_disposition(conn: sqlite3.Connection) -> _DeriveDisposition` — implement guarded source-scoped reconciliation/recovery under the caller's `BEGIN IMMEDIATE`, preserving validated checkpoint semantics and explicitly separating global scan disposition from permitted source recovery. A skipped global scan may carry proved source-recovery writes/counts, but its reason and absent `scanned_bound` cannot certify global progress; revise the private disposition documentation/callers accordingly. `_derive_usage_incremental_conn(conn) -> int` remains its count-only compatibility wrapper.
- Reuse `inspect_usage_candidates` (ENH-3744), including its correspondence and internal matched-observation/context evidence, and `read_source_derive_completion` / the committed generation/order/pending state (ENH-3745). ENH-3744 does not grant mutation permission. One transaction-scoped private reconciliation planner consumes these shared facts and computes insert, value replacement, supported qualification action, no-op, preservation with pending work, or proved-conflict invalidation. The action table below separates a proved no-op from an untouched but unresolved observation. Preflight the participating candidate scopes together before pricing or writing, so two newly discovered conflicting native responses cannot be priced sequentially before either has a committed match; guarded writers consume that plan before pricing or mutation. Private action-plan data is allowed, but no second native recognition/coalescing algorithm, competing pure candidate proof, mapping ledger or migration belongs here.
- The landed `UsageCandidateProof` carries correspondence/matched IDs/context/supplier positions, not a complete mutation target or generation certificate. Factor shared retained recognition/coalescing evidence from `usage_proof.py` and the existing writer into one internal target handoff used by proof/planner/writer. Collect through `usage_proof_scope`, preserving its public correspondence contract and bounded whole-scope limits. A proof-limit/unavailable outcome permits no usage-value/requalification action or affirmative supplier/frontier certification from that affected reconciliation scope, and no hold release. It still permits bounded pending/source-completion invalidation and independently valid raw acquisition/cache work. An incomplete collection cannot authorize observation conflict demotion, discard an existing supplier/context witness, or certify a partial target plan; conflict invalidation requires its complete bounded identity/context proof.
- Add the internal typed reader `read_pending_recovery(conn: sqlite3.Connection, source_path: str, *, schema: str = "main") -> tuple[PendingRecovery, ...]` in `usage_source_state.py`. Frozen `PendingRecovery` carries `pending: SourcePending`, `head_revision: int`, `obligation_revision: int` and validated `original_acquisition: OriginalAcquisition | None`; malformed authority withholds permission while retaining the outstanding obligation. Read the existing `original_acquisition_json` and head/obligation revisions in the caller's transaction; never treat the current `pending_obligations(...).original_acquisition` default as acquired authority. This is an extension over existing storage, not another journal/migration or public CLI field.

- Factor transaction-only acquisition staging from `finalize_source_refresh` using `begin_attempt`, `_with_verified_session` and `record_source_acquisition`. Both atomic `refresh_usage_source` paths stage the verified acquisition scope/head before reconciliation, then finalize from post-write proof. Reuse a matching staged acquisition without another write; unchanged retries neither restage it nor merge identical pending merely to poll it. Verified raw-only ingestion stages acquisition and usage-pending when canonical coverage/native identity/source stability are proved; acquisition alone never publishes semantic completion. Carry that same scope and the returned revisions through planning, witness writes, pending and finalization. An in-memory generation or unverified/headless historical raw does not supply acquired authority. Keep the narrow stored-raw audit allowance below independent of this staging.

### Call Path

Verified raw acquisition → native identity/coverage/stability check → acquisition-head staging with usage-pending → reconciliation → post-write proof/publication, all under the acquisition caller's transaction when atomic. Independently committed raw-only acquisition leaves the same durable handoff for later retained-only derive; phase-1 parser refresh additionally records its scoped original-source recovery authority and cache work.

`backfill_usage_incremental` → `_derive_usage_incremental_disposition` → shared bounded retained scope/recognition + committed generation/order/recovery state → transaction-scoped reconciliation plan → guarded `_backfill_usage_events` → post-write semantic proof + scoped usage acknowledgement/completion. `rebuild` and `refresh_usage_source` consume the same action plan; `usage_refresh.refresh_raw_events` commits acquisition and pending protection across its two-phase workflow, even without prior tracking. The compatibility count wrapper does not own mutation or certify completion.

Preserve schema-member qualification and prune dry-run overlay semantics for every new query.

### Decision Rules

- Evaluate candidates against the committed observations **before** any reset, per-Codex-source catch-up, rebuild or parser-refresh deletion. Replace broad usage delete/reinsert with source-scoped reconciliation; unchanged unheld rows need the same cost/identity preservation as held rows. A prospective insert/replace is not committed representation. `prune` consumes proof and writes protection only; it does not derive usage or invoke pricing. Dry-run uses the same proof/context plan in one read snapshot and writes nothing.
- Enforce the private reconciliation action plan at every replay writer seam, including qualified Claude, Codex and unkeyed/other-host audit paths. The planner reuses ENH-3744's native candidate/coalescing/context evidence, validates host/session/channel/native identity across replay envelope, payload and matched committed observation, and combines it with ENH-3745's committed generation/order evidence where the action requires that authority before permitting pricing, insert or update. Within this same planner, an exact surviving stored raw identity with compatible payload/envelope identity and no ambiguous protected overlap may authorize a first-time unqualified audit insert under existing producer/pricing semantics, or an unchanged exact-link audit no-op, without an acquired source head. This grants no promotion, value replacement, affirmative supplier/context certification, source completion, figure as-of publication or hold release. Missing acquisition state alone cannot suppress this supported other-host audit path; rawless inputs and held/wildcard ambiguity remain fail-closed. Correspondence alone is not mutation permission. An exact surviving raw link with compatible envelope can prove an unkeyed audit replay is already represented; it must not plain-INSERT a duplicate or hit the unique raw-link index. Identity disagreement preserves existing value evidence and reports unprovable; it cannot manufacture a qualified observation. Keep all no-op paths free of pricing and SQL updates to the observation. The private `_backfill_usage_events(list[Path])` path has no durable raw identity and cannot authorize observation mutation, pricing or positive publication: fail closed for rawless direct-file inputs. Keep direct/stored adapter recognition parity as a read-only test; normal derivation uses the existing raw-acquisition path and stored cursor rather than an exception to the planner.
- Compare Codex native-response candidates with relevant committed observations across sources, including when only one source is being caught up. Apply the existing host/request plus thread/turn/value dedup contract, rather than relying on the writer's invocation-local `native_seen`. An identical proved copy requires compatible qualification evidence and preserves the survivor's actual supplying source/position. A proved native identity/value conflict or contradiction of consumed model/context is a separate conservative qualification invalidation: atomically mark every affected committed observation's provenance unknown and clear only the qualification facts contradicted by that proof, preserving row IDs, numeric values, stored historical costs, timestamps and supplying witnesses. Retain conflicting copies as unqualified audit evidence under the existing producer contract without pricing; report unprovable/incomplete and retain the required conflict evidence/pending disposition. This cannot rely on future reader integration because current canonical readers gate on stored provenance. Missing context, older/unchanged replay and compatible equal-value copies do not justify demotion; equal counts with proved incompatible models/context are not an identical copy. Compare participating retained targets before pricing, including first derivation with no committed observation and same response ID in different threads. Matching session IDs alone cannot define the conflict population. Extend the shared bounded scope/target handoff for this preflight, without an unbounded host-wide scan or a competing conflict algorithm. Ordinary replay or an unrelated closure cannot clear proved conflict invalidation; recovery requires compatible proof that actually resolves it, using ENH-3745's shared bounded pending evidence if persistence is needed, not a competing conflict ledger.
- Existing `source_line_no`/`source_ordinal`, verified native stream/session and compatible committed source-generation witnesses may support ordering. A raw ID orders ingestion only. If generation/order cannot be proved after pruning, preserve the retained observation and report mutation unavailable; do not invent compatibility or accept rollback as a risk. ENH-3745 owns a minimal durable witness if existing state is insufficient.
- Reconcile a logical request's proved target state against its committed observation before issuing writes. Within an unambiguous retained generation, select the newest valid native snapshot under the producer's actual coalescing/order contract instead of walking older snapshots through temporary replacements or pricing them. A pruned or ambiguous supplying generation permits mutation only if an independently sufficient committed witness establishes compatibility/order. Neither equality of numbers nor larger raw IDs makes target state or no-op correspondence provable.
- **MP3 gating:** preserve today's context-only Codex requalification for fully retained, unheld sources when a genuinely new compatible append supplies the missing closure/model context. Require the complete relevant request-span/model/closure/conflict/dedup dependencies, preserve the existing request row, numeric components, value-supplying position/timestamp and stored historical cost, and update only proved qualification facts and the minimum internal consumed-context witness. Pricing is allowed only once for a newly proved eligible unpriced observation under existing semantics. Missing/replayed context or an identical duplicate copy cannot promote or downgrade a row. This is a distinct proved qualification action, not unchanged replay, numeric replacement or automatic legacy promotion.
- **Verified original-source recovery is a separate gating qualification action:** on a fully retained, unheld compatible source, explicit successful parser refresh may certify a formerly NULL ingest-time contract. A linked audit observation can acquire only the qualification/key/dependency facts proved by that acquisition when its exact raw link, envelope/native identity, model and every captured numeric component match the recovered candidate, with no unresolved acquisition gap/conflict. Preserve ID, numeric values, timestamps, actual supplier and existing historical cost; an eligible previously unpriced row may be priced at most once. Use ENH-3745's scoped durable refresh-acquisition evidence across the two phases; ordinary replay, a persisted marker or matching values alone cannot invent this permission. Missing observations take the ordinary proved insertion path. A contradictory/partial captured observation stays protected and unprovable; same-position parser recovery is not a newer value snapshot. Held/pruned qualification recovery remains deferred.
- **Phase 2, non-gating:** context-only promotion for held/pruned or beyond-gap requests, including the richer qualification frontier and aggregate beyond-prefix as-of integration. Until then such audit rows remain audit and cannot borrow an earlier successful prefix as affirmative figure as-of proof. A gap inside required context blocks qualification in every phase. Digest continuity remains deferred under ENH-3745's fail-closed fallback.
- Check for unchanged/older/protected replay before calling pricing. No replay or rebuild reprices an unchanged retained observation. New or proved-changed requests follow existing pricing semantics; stored historic costs are not recalculated as a side effect of proof.
- A proved value replacement atomically updates the minimum committed applied-value supplier/source-generation/native-position witness with its numeric values. The gating full-retained Codex qualification action updates the minimum witness for the context actually consumed without pretending that a newer numeric snapshot supplied the values. No-op replay preserves both witnesses along with cost/metadata. ENH-3745 owns missing persistence; only the aggregate beyond-prefix as-of integration is Phase 2. A Codex dedup survivor retains its actual supplying source/position; another copy cannot substitute a convenient selected-source boundary.
- Persist usage-pending for every incomplete scanned source/scope before advancing a valid/bootstrap scan high-water, including unheld proof-limit, unavailable identity/generation/context and conflict outcomes. Use ENH-3745's shared scoped disposition with the actual captured range/reason and revision; use whole-source/unknown bounds when a failed collection cannot prove a narrower range. Scheduling scope alone grants no acquisition or mutation authority. Retry every outstanding usage component below/equal the checkpoint independently of hold presence, including when raw max is unchanged; do not repeatedly merge an unchanged obligation merely to poll it. This issue owns iteration/retry and resolution; ENH-3745 owns its storage/scan validation. Raw-ID bounds schedule retries only; native context/order decides recognition and mutation. Recognized omission, already represented audit and excluded channels do not create perpetual pending merely because they cannot qualify.
- **Established unusable checkpoint recovery/publication:** distinguish source recovery from global checkpoint repair for established absent, partial, version-changed, invalid, contradictory or sequence-unprovable metadata. Source-scoped recovery may consume committed pending under independently valid acquisition/generation/action proof without relying on or changing the unusable floor; narrow qualification still requires its original-acquisition authority. Until global repair is proved, retain the exact checkpoint metadata and global skipped reason. Global repair requires one transaction to verify the exact classified metadata, plan/scan the entire retained raw population through captured bound `B` under compatible current derive scopes, obtain a usable allocation-sequence check, and leave no unresolved usage work at/below `B` or proof-limit/unavailable scope. Publish only the freshly scanned `B`, never `max(untrusted_prior, B)` or a bound inferred from one recovered source. Persist source outcomes and publication atomically; failure preserves prior metadata. This scan floor certifies retained scheduling only: it cannot certify pruned history, unwitnessed observations, source completion or hold release. An empty retained set/sequence-unprovable state does not repair a discarded positive floor. Older-generation/version obligations are not silently relabeled or cleared; unresolved work remains pending and protected. Any chosen derive-version bump must justify a tested explicit recovery/retirement policy for those obligations in the Resolution, or retain the current version.
- Release only the exact source-local hold whose entire covered surviving usage population is proved safely reconstructible from retained compatible native evidence for its current values and qualification dependencies, with every generation/version-scoped pending candidate and acquisition failure resolved. Preserved observations, absent pending metadata, or an empty retry set are not sufficient proof. No equivalent row-level conservation guard exists today; do not add a hypothetical guard escape. If missing/deferred generation evidence prevents reconstructibility proof, retain the hold while allowing separately proved safe additive work. Per-source release never clears a NULL-source wildcard/population hold or another source's protection, and cannot certify an inventory of older already-pruned history. An unresolved proved conflict remains a release and global-repair blocker; this conservative contract may retain protection indefinitely. Demotion is not resolution, and no terminal-conflict shortcut clears pending or releases a hold.
- Compute reconciliation proof, protect/replace observations and update hold/source-progress outcomes in the caller's existing `BEGIN IMMEDIATE` transaction. Forced failure rolls everything back. ENH-3744's prune proof/protection/deletion transaction remains independent: MP3 does not derive usage in prune or take ownership of its veto algorithm.
- Extend the shared `invalidate_usage_dependencies` seam for preservation-aware actions before replacing its destructive callers. Preserve applied-value witnesses for unchanged/preserved rows; invalidate only contradicted context/qualification facts on conflict, and replace the supplier/frontier atomically on actual permitted changes. Extend `write_observation_witness` so an `invalidated` qualification may retain independently valid, uncontradicted context dependencies through the same helper; its aggregate status stays non-affirmative and that residual frontier cannot qualify a row or prove figure as-of. Preserve dependency-role/scope validation and supplier evidence; remove a role only when the complete conflict proof contradicts it. Missing/proof-limited evidence records pending without demoting the observation or erasing its witnesses. Retain reverse-dependent source invalidation and older historical boundaries, but assign `raw_cache` only to scopes whose parser-derived caches actually need rebuilding. A copied source depending only on another source's usage/context gets usage pending, not fabricated cache work. A no-op cannot erase witnesses or create new obligations merely because rebuild/catch-up was requested.
- For narrow original-source recovery, validate the stored acquisition authority's exact source/generation, acquisition and derive versions, certified range and acquisition revision against the recovery being consumed. Capture the current head and obligation revisions for CAS acknowledgement; never equate the acquisition revision with the later mutable head revision. Malformed/stale/wrong-scope authority, partial consumption or a merged obligation extending beyond the acquisition certificate cannot authorize recovery or clear work. Chain expected head/obligation revisions through permitted writes in the same transaction, then acknowledge against their latest resulting revisions; never substitute an unrelated newer revision or clear unconsumed components. Acquisition authority remains independently validated.
- Preserve the public two-phase parser-refresh workflow with stable raw IDs: for an existing line whose verified host/session/envelope/native position and ENH-3751 canonical field-preservation checks pass, update allowed parser payload additions and NULL→contract-marker recovery in place; append genuinely new native lines. Keep existing raw IDs, observation links and value-supplying provenance intact. Refuse incompatible metadata, contracts, dropped/changed fields or source changes under the existing refresh semantics; do not delete/reallocate verified existing raw rows, blindly relink observations by path/line, or introduce a mapping ledger. Ordinary retained replay cannot acquire missing ingest-time contracts by itself.
- Commit parser raw updates/appends and ENH-3745's scoped refresh-pending/invalidation disposition together while retaining old usage and truthful historical boundaries. Phase 1 must create or update the acquisition head through `record_source_acquisition` for a fully verified original-source range, including a previously untracked raw-only/legacy source and verified appends beyond its old acquired boundary. Persist the certified acquisition boundary/witness and `OriginalAcquisition` authority with both pending components under the same compatible generation and chained revisions; absence of an old head/cursor cannot silently drop this work. This proves acquisition only, not usage completion or historical lineage. An unavailable/incompatible generation or rejected range stays incomplete and supplies no recovery authority. An unchanged retry writes no raw or observation rows but still reports committed `needs_rebuild` through API and text/JSON until every applicable refresh component resolves. Preserve unrelated sources' progress; do not clear global checkpoint metadata or create a second refresh journal.

A counts dictionary, normal return or zero inserts never proves resolution. Text/JSON retain the flag and report incomplete while work remains; only full resolution permits the existing success message. Do not promise repeated rebuild will resolve permanently unprovable/over-limit evidence. Keep existing JSON/result keys and use the shared state reader rather than a new public result field.

### Reconciliation Actions

Evaluate the complete target scope before any priced write. These are policy rows for the shared planner, not another recognition algorithm. Evidence requirements are action-specific: absent qualification-only context does not block an otherwise proved audit insert/exact-link no-op, while incomplete required peer/conflict evidence preserves pending. Complete independent native conflict proof or an outstanding unresolved conflict takes precedence over an otherwise unchanged/older numeric target; ordinary older replay alone is not conflict proof. A preserve-pending outcome leaves observation fields/witnesses untouched and keeps the affected scope incomplete. Returned counts increase only for actual inserts.

| Proved target condition | Observation action | Witness/publication effect | Pricing |
|---|---|---|---|
| Distinct eligible request with sufficient acquired generation/native evidence and no protected overlap | Insert once | Record actual supplier and consumed context; publish only after post-write proof | Existing insertion semantics |
| First-time unqualified audit with exact stored raw identity and compatible envelope, no ambiguous protected overlap | Insert audit once | No affirmative generation/context/completion/as-of certificate | Existing first-insert semantics only |
| Semantically unchanged target, compatible identical copy, or proved older native snapshot under the producer contract | No-op; preserve every stored field | Preserve actual supplier/frontier; no invented historical lineage | None |
| Strictly newer compatible target whose producer permits snapshot replacement | Replace from the final selected target; preserve row ID | Atomically replace applied-value supplier and actual consumed context | Once for that changed target under existing semantics |
| Gating new Codex closure or matching audit original-source recovery with its scoped authority | Qualification only; preserve captured numbers/value supplier/time/existing cost | Record only proved qualification/key facts and consumed context | At most once for newly eligible previously unpriced usage |
| Captured audit values disagree with same-position original-source recovery, without independent native conflict proof | Preserve pending; no numeric correction | Keep old evidence and recovery incomplete | None |
| Complete native conflict proof, including incompatible consumed context | Conservative qualification invalidation; preserve IDs/numbers/cost/time/supplier; retain conflicting audit evidence under existing producer contract | Invalidate only contradicted facts; persist unresolved conflict/reverse-source work | None |
| Conflict remains unresolved on an already demoted target | Preserve pending; no replacement or re-promotion | Keep conflict evidence; no completion, global repair or hold release for affected scope | None |
| Evidence required for the proposed action unprovable, protected overlap ambiguous, or shared proof budget exceeded | Preserve pending; no partial usage plan or conflict demotion | No affirmative certificates; retain existing witnesses and record bounded outstanding work | None |
| Rawless direct-file helper input | Refuse observation work | No positive publication | None |

A same-position disagreement is not a newer snapshot and does not itself prove native conflict: distinguish contradictory captured legacy values from independently proved native copies. Likewise a larger ingestion ID cannot select the newer-target row. Parameterized policy tests cover applicable producer contracts, with public-call regression tests for transaction and state effects.

### Landing Mechanics, Interactions and Constraints

- **ENH-3751 (done 2026-10-06) changed the refresh seams this issue edits.** `usage_refresh.refresh_raw_events` now compares canonical (history-sanitized) payloads in both stored columns, refuses per-line metadata/contract changes (`source_metadata_changed`, `usage_contract_changed`, `existing_payload_not_preserved`, `parser_changed_during_refresh`) and promotes a NULL `usage_contract` monotonically — a persisted marker is never changed. `_refresh_codex_usage_source` first-cursor certification uses the same canonical comparison. Preserve all of this; "the existing verified original-source refresh's qualification recovery" above is that NULL→marker promotion, distinct from the context-only qualification promotion on `usage_events` specified here.
